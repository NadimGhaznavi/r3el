[До змісту документації](/uk/)

R3el задає метадані інвентаризації як літерали у `r3el/constants/DR3el.py`. CMDB читає цей файл, не виконуючи його. Зареєструйте програму як `R3el` і повторно проскануйте встановлену робочу версію, щоб виявити її випуск і каталог MariaDB на тому самому сервері. CMDB поки не збирає мережеві оголошення, проте вони описують стандартні прослуховувачі та вже визначають типові параметри R3el.

| Оголошення | Призначення |
| --- | --- |
| `CMDB_DATABASES = (("R3el", "r3el"),)` | Назва локального каталогу MariaDB. Встановлення, перевірка оновлення й видалення знаходять каталог за міткою. |
| `CMDB_NETWORK`, `http` | HTTP-сервер керування, типово `0.0.0.0:42220`. |
| `CMDB_NETWORK`, `backend` | ZeroMQ-сервер пакетів, типово `127.0.0.1:42221`; цей порт використовує і клієнт керування. |

Оголошення бази даних не містять облікових даних чи параметрів віддаленого з'єднання. Їх і надалі задає `/etc/r3el/database.env`. Вихідний порт MariaDB і незалежно керований спільний сервіс Qwen налаштовуються окремо. Тимчасові прослуховувачі ZeroMQ для операцій зіставлення отримують динамічний порт.

## Зміна мережевих параметрів у робочому середовищі

Інсталятор створює `/opt/prod/r3el/conf/r3el.json` на основі `CMDB_NETWORK` лише за відсутності файлу й зберігає наявний вміст під час перевстановлення й оновлення. Шлях визначає `DR3el.BASE_DIR`. Файл не містить секретів і доступний обліковому запису служби. За його відсутності використовуються стандартні значення:

```json
{
  "network": {
    "http": {"interface": "127.0.0.1", "port": 43220},
    "backend": {"port": 43221}
  }
}
```

Пропущені прослуховувачі та поля успадковують стандартні значення. Дозволені тільки `network`, оголошені призначення та поля `interface` й `port`. Інтерфейс має бути рядком IPv4, порт — цілим числом від 1 до 65535. Неправильний JSON або параметри спричиняють помилку із зазначенням файлу й поля; некоректний файл **не** замінюється типовими параметрами.

`Configuration` визначає налаштування один раз на процес. `Network.binding(use)` повертає адресу прослуховування й порт. `Network.destination(use)` для локального клієнта замінює `0.0.0.0` на `127.0.0.1`, зберігаючи конкретні адреси. Так Control підключається до сервера пакетів.

Параметри `--host`, `--port`, `--zmq-endpoint` у Control та `--zmq-endpoint` у сервері пакетів перевизначають налаштування окремого запуску. Якщо обидва процеси мають спілкуватися, ручне перевизначення кінцевої точки слід застосувати до обох.

## Застосування змін

Відредагуйте робочий JSON-файл і виконайте:

```sh
/opt/prod/r3el/scripts/services.sh restart
```

Перед зупинкою будь-якої служби команда перевіряє параметри, після чого запускає Control і сервер пакетів із новими значеннями. Перезапуск перериває активний пакет, тому виконуйте його лише коли сервер пакетів можна зупинити. Спільний сервіс Qwen має бути готовий перед обробкою. `services.sh start` також попередньо перевіряє конфігурацію. Встановлення й оновлення перевіряють її до зупинки служб; потім запускають Control, залишаючи сервер пакетів зупиненим.

Зміна робочих параметрів не змінює стандартну інвентаризацію в CMDB.
